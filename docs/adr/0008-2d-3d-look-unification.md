# One parchment, one grade: the 3D sheet carries real content and shares the DOM's texture

Status: accepted (2026-10-04).

The 2026-10-04 review found the 2D→3D seam reads "night and day": the 3D desk is a different world from the flat parchment column. Fix is three-part. (1) The 3D parchment sheet is content-bearing: the QUESTS content (same fonts, same palette) is rendered onto the sheet's texture, so a large screen shows the actual page from the wide desk view and the zoom-in is a change of magnification, not a change of material. (2) Sheet and DOM column share ONE generated parchment texture (procedural paper + aging, deckled edges, faint foxing, subtle creases, small scorch marks at dividers — all subtle), so the surface is literally the same object. (3) The 3D scene and the DOM page get a matched color grade, so the crossfade lands between near-identical frames. The old flat decorative roll (blank paper with no content) is rejected: it is the root cause of the seam. Consequence: content edits must regenerate the sheet texture (build step or runtime canvas), and the DOM column's look is constrained to what the shared texture can express. Nuance added at build (critic pass 2, 2026-10-04): "near-identical frames" includes framing — the read-framing camera is pulled back so the sheet spans the same portion of the viewport (with wood margins) as the DOM column does, because a full-bleed-to-margined cut reads as a scene change no matter how well the grade matches.
